# 教材ページの標準仕様・数学的厳密性・演習

作成日: 2026-09-11 / 次期編集仕様。現行schemaを自動的に変更するものではない。

## 1. 目標

最初に読む量は少ないが、必要な情報は深く確認できる教材にする。「やさしさ」を、前提の削除・不正確な比喩・途中式の省略で実現しない。基本の説明を適切な長さにまとめ、導出や証明は別の表示層へ置く。

## 2. 一つの正本ページの4層

|層|初期表示|内容|完了の判定|
|L0 見取り図|開く|何のための概念か、短い説明、代表図|読書記録のみ。習得とは判定しない|
|L1 基本・使い方|開く|定義の入口、式と記号、必須条件、数値例、注意、確認問題|対応する理解・計算・解釈の目標で確認|
|L2 導出・納得|閉じる|なぜその操作をするか、途中式、図とのつながり|導出を追えるか、別の数値でも説明できるか|
|L3 厳密な証明・発展|閉じる|仮定、定理、補題、証明、例外・反例、関連理論|必要なコースだけ証明・条件確認を評価|

L2は、L3の不完全版を無言で掲載する場所ではない。略した部分と詳細への入口を明記する。L3でも一から数学の全公理を証明し直す必要はないが、使う定理と条件を明らかにする。

所要時間の表示は初期には編集上の目安として扱い、実利用で調整する。長さを埋めるために文章を増やさない。

## 3. ページ内の標準順序

1. タイトル、中心的な問い、学習目標、対象コース・表示層。
2. 前提知識。必要な数学を短く確認して元の場所へ戻れるリンク。
3. 30秒で分かる説明。比喩だけで終わらず対象を明示。
4. 図・表・小さなデータによる直感。
5. 基本的な定義、使用条件、公式、記号表。
6. 解き方が追える数値例。問題→方法を選ぶ理由→計算→解釈。
7. よくある誤り、使えない場合、似た概念との違い。
8. 理解確認とヒント・解答。導出を読まなくても基本問題は解ける。
9. 導出の折りたたみ。
10. 厳密な証明の折りたたみ。必要に応じて論点ごとに分ける。
11. 発展問題・再現コード・関連する手法への接続。
12. 次の学習、出典、更新・確認情報、訂正受付。

説明に不要な層は省略できる。研究倫理やグラフ選択などに無理な「数学的証明」を作らない。

## 4. 主張の種類を区別する

|種類|表示すべきもの|正規分布での例|
|定義|何をそう呼ぶか、定義域、記号の慣習|密度を指定して正規分布族を定義する|
|定理・性質|仮定と結論、証明または正確な参照先|密度の積分が1、平均・分散、線形変換|
|導出|出発点、変換操作、使う事実|正規化定数や一般の平均・分散を持つ式を求める|
|モデルの仮定|現実の何を近似しているか、検討方法・限界|ある集団の測定値を正規分布で近似する|
|数値結果|計算法、精度、丸め、再現条件|1.96より右の確率が約0.025|
|直感・比喩|説明の補助であり、証明ではないこと|平均を中心に山が広がるイメージ|

「正規分布の式を証明する」は、一つの曖昧な見出しで済ませない。何を定義し、何を導き、何を証明し、何を現実に仮定したかを分ける。定義から『全ての現実データが正規分布に従う』とは導けない。

## 5. 証明ブロックの必須項目

```yaml
claim_id: normal-normalization
claim_kind: theorem
statement: 正規化した密度の全実数上の積分は1である
assumptions:
  - 定義された実数値の変数を扱う
prerequisites:
  - 多重積分
  - 非負関数の積分順序交換
  - 極座標変換
proof_status: full
proof_dependencies:
  - Tonelliの定理
  - 多変数の積分変数変換公式
review_status: self_checked
```

これは仕様例であり、現在のfrontmatterへそのまま追加する指示ではない。

`proof_status` は `full`（明記した前提に対して証明を完結）、`sketch`（概略）、`referenced`（外部の証明を特定）、`not_applicable`（証明対象でない）を区別する。公開前の確認状態は別フィールドにする。詳しい式が並んでいるだけで `full` としない。

### 証明の受入条件

- 仮定と結論を別々に読める。
- 記号が初出で定義され、確率変数と実現値、母数と推定値を区別している。
- 等号・不等号・極限・微分積分の交換に必要な根拠がある。
- 密度の変換では値域とヤコビアンを確認している。
- 「平均0・分散1だから正規分布」等、性質の逆を誤って使っていない。
- 近似等式を通常の等号で書かない。漸近結果と有限標本の結果を区別する。
- 必要な補題を本文または参照先で確認できる。自分自身を根拠にする循環がない。
- 通常の定理と境界・例外条件を混同しない。何を仮定しなければ壊れるかを説明する。
- 数値実験は補助確認であって数学的証明の代わりではない。

## 6. 初学者向けであっても隠さない条件

重要な使用条件はL1で見える位置に置く。条件の理由をL2/L3に置くことはできる。

|内容|最低限見える必要がある注意|
|正規分布|どの量が正規分布に従うと仮定されているか。標準化しても任意の分布が正規分布になるわけではない|
|中心極限定理|扱う版の独立性・同一分布・有限分散等の条件。元データではなく標本平均等の分布についての主張|
|t法|独立性、モデルの前提、近似で使う場合の位置づけ。「nが30以上なら常に大丈夫」としない|
|信頼区間|何を繰り返したときの被覆率か。ベイズの信用区間とは区別|
|p値|帰無仮説のもとでの確率であり、帰無仮説が真である確率そのものではない|
|非有意|差がないこと・同等であることを自動的には示さない|
|回帰・相関|関連や予測と因果効果を区別する。単純な有意性だけで因果を結論しない|
|検定の使い分け|データの型だけでなく、対応、独立性、研究目的、仮定を確認|

上表は編集用チェック項目。各教材では必要な範囲に絞って自然に説明し、すべての注意を毎回長く繰り返さない。

## 7. 数式・表記の規則

- `X` と `x`、`μ` と標本平均、母分散と標本分散を混同しない。
- `N(μ,σ²)` の第2引数を分散と明記する。標準偏差を取るソフトの引数とは区別する。
- 幾何・負の二項分布、ガンマ分布、尖度、標本分散の分母など、慣習が分かれる定義には「本サイトの定義」と他の慣習を示す。
- 公式は「式の役割→式→記号→条件→例」で説明する。
- 途中式を一行に詰め込まない。式の変形ごとに短い理由を付ける。
- 日本語の用語を主とし、英語と別名は索引・初出の補足に使う。
- 図の面積・軸・単位・標本数・生成条件を記載する。イメージ図を実測結果として扱わない。
- 小数の丸めは最後に行う。計算機上の丸め誤差と概念上の近似を区別する。

## 8. 演習の設計

各中心的な学習目標に、少なくとも理解を確認できる独自問題を紐付ける。初期の標準教材では「概念」「計算」「解釈・誤り発見」を各1問程度から始めるが、数を埋めるための同型問題だけにはしない。

|形式|測るもの|例|
|概念選択|対象と条件の区別|確率密度の高さは確率か|
|数値入力|計算手順・単位・丸め|平均とSDから境界を標準化する|
|グラフ解釈|式と図の対応|片側2.5%の領域を選ぶ|
|方法選択|目的・デザイン・仮定|対応ありデータでどの差を分析するか|
|誤り発見|典型的な誤解|非有意だから差がない、という説明の問題点|
|記述・導出|根拠と条件を含む推論|変数変換で密度を導く|

### 一問に持たせるデータ

問題ID、対象目標ID、必要な前提、難度、問題形式、問題文、選択肢または入力条件、解答、段階ヒント、計算過程、誤答理由、誤解タグ、数値許容誤差、独自作成・出典情報、確認記録、問題版。

数値入力では絶対・相対誤差や単位を明示する。自由記述では同値な正しい答案を認め、採点基準と模範解答を表示する。初期版でAI自動採点の正確性を仮定しない。

答えを見た後の同一問題の正答だけで習得済みにしない。別の数値・別の文脈、または時間を置いた確認を復習候補にする。再確認間隔は設計値として扱い、効果が実証済みの固定値とは説明しない。

## 9. 数学・説明・出典を分けて確認する

制作時には、(1)数学の正確性、(2)初学者に追える説明、(3)範囲・出典・問題の対応、(4)表示と操作、を別の観点で確認する。独立した担当者による確認ができたときだけ、その事実を記録する。作成者の自己確認を「第三者監修済み」と表示しない。

AIは下書きや確認に利用できるが、同じ出力の再言及を独立した根拠として扱わない。出典に到達できない引用、存在を確認できない書名・論文・ページ番号は掲載しない。
